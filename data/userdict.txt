# ============================================================================
# jieba 自定义词典 —— 一行一个词
#
# ★ 为什么必须有这个文件（而不是"jieba 默认词典够用"）：
#   jieba 的默认词典是从通用新闻语料训练出来的，它【不认识】电商品类词。
#   不加词典时实测的切分结果：
#       充电宝      → 充电 / 宝          ← 两个词都废了
#       蓝牙耳机    → 蓝牙 / 耳机        ← 勉强，但词云上会拆成两半
#       无线充电器  → 无线 / 充电 / 器   ← "器" 是个单字，会被长度过滤丢掉
#       降噪耳机    → 降噪 / 耳机
#   结果是词云上飘着"充电""无线""耳机"这种东西，
#   完全看不出"这个品类在卖什么"——而词云的全部价值就在这里。
#
# 格式（jieba 的 userdict 格式）：
#     词语 [词频] [词性]
#   词频可省略（省略时 jieba 按"能组成的词数"自动推算）。
#   ★ 这里【刻意不写词频】：
#     写了大词频（比如 1000000）会让 jieba 在长句里强行按这个词切，
#     把 "快充数据线" 切成 "快充" + "数据线" 而不是 "快充数据" + "线"——
#     这正是我们要的。但词频写多大纯属拍脑袋，而且一旦写错很难排查
#     （症状是切分结果莫名其妙），所以交给 jieba 自己推算更稳。
#
# 空行和 # 开头的行都会被跳过（jieba 原生支持 # 注释，这里保持一致）。
# ============================================================================

# 七、拉丁字母词（★ 不写进来就会被切成单个字母）
#
# ★ 这里对应 plan 里的一个坑：早期草稿写的过滤规则是"丢弃纯 ASCII 词"，
#   那会亲手杀掉 iPhone / WiFi / Type-C / USB ——
#   而它们恰恰是数码品类里信息量最高的词。
#   正确做法是保留长度 ≥3 的 ASCII 词（见 stats.py 的过滤规则），
#   再把真正的型号噪声交给停用词表按需处理。
#
#   Type-C 这类带连字符的词必须进词典：不进的话 jieba 会切成
#   "Type" + "-" + "C"，"-" 和 "C" 都会被长度/纯符号规则丢掉，
#   于是"接口是 Type-C"这条信息在词云里彻底消失。
